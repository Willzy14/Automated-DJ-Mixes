## FOUND UNASKED

1. **The `--track` case fold uses Python `str.lower()`, which does not match Windows' own ignore-case rule.** On NTFS, "Σ.wav" (U+03A3) and "ς.wav" (U+03C2) are the same file to Windows (`CompareStringOrdinal` ignore-case returns equal), but Python's `.lower()` maps Σ to σ and leaves ς as ς, so `e.name.lower() == want.lower()` is False. A project whose Audio folder holds such a name would be refused for a `--track` that Windows would open. All 20 real corpus filenames are ASCII, so this is latent. `os.path.normcase` is not the fix either (it is a no-op on Windows); a `str.casefold()` comparison would over-match rather than under-match, and matching the OS rule needs `CompareStringOrdinal` or an actual `open()` attempt.

2. **A bool `end_sec` on the last section makes the clamp clamp to 1.** `if end_sec > 0` is True for `True`, and `min(x, True)` is `min(x, 1)`, so all four hints would collapse to 1.0 s. `isinstance(end, bool)` is excluded from the reader's `ends` list, so the reader would then see a `track_end` from another section. No writer emits a bool (`round(downbeat + s1 * sec_per_bar, 2)` is always a float), so this is hand-crafted-file only.

3. **`--track` is still unvalidated on the non-hints path.** `wavs = [audio / args.track] if args.track else sorted(audio.glob("*.wav"))` runs before the `--write-hints` block and is not guarded by the new checks, so `stem_detector.py <project> --track ../elsewhere.wav` still runs `detect()` on a file outside `Audio/`. Pre-existing and explicitly listed as accepted for the empty-string case; the traversal case is not covered by that acceptance. The `--write-hints` path is now strict, which makes the asymmetry visible.

4. **`--track` on the hints path bypasses the `Audio/*.wav` glob, so a wav that `iterdir()` sees but `glob("*.wav")` would not is now selectable.** The two selectors differ: `glob` matches `*.wav` case-sensitively on some platforms, `iterdir` plus `suffix.lower()` matches `.WAV` too.
