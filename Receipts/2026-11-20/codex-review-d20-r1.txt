### Cache and overwrite findings

- **A silently accepts weak caches.** On the first run after the upgrade, a legacy cache left by the old `--write-hints` command is reused without warning, even if the user now passes `--kick-model`. A cache explicitly marked `analysis.kick_model: false` gets the same treatment. A valid legacy Phase 1a cache is also reused without a write. The code already emits `signals.kick_presence_source`, which can distinguish legacy model output from legacy energy-threshold output when that field is present.
- **The shape check accepts unrelated or unusable data.** Save `{"track":"Other","bpm":128,"sections":[]}` as `SECTIONS_STEM_T.json`. The command reports a cache hit and writes four synthetic timings for `T.wav`. A complete cache for an older audio file with the same name also passes. Require usable sections, an audio fingerprint, and compatible detector and configuration metadata.
- **B, D and E can disagree about the source of truth.** With `{"bpm":128,"analysis":{"kick_model":true}}` on disk, the missing `sections` triggers fallback. The real `detect()` gets BPM from that cache, computes kick-off sections, and is refused permission to replace the JSON by the guard. It still returns its result, and the CLI publishes weak hints. I reproduced this with warnings and the original file intact.
- **C records the request, and D trusts it.** A provider exception or literal `None` result aborts before the write. A provider returning `[]` takes a different path. It gets padded to all kicks off, is marked `kick_model: true`, and silently replaces a good marked file. I reproduced the replacement. Validate the provider's beat data before marking it usable or allowing the write.
- **E is incomplete.** `signals: null` raises an uncaught `AttributeError`, BPM `0` raises `ZeroDivisionError`, and a read failure can raise `OSError` before fallback. A top-level array reaches fallback, then the BPM resolver rereads it and raises `TypeError`.
