## HOW ROW FIELDS MAP TO RESOLVER ARGUMENTS

`artist` and `title` go to `scan()` as stored. The resolver normalizes case and punctuation. A change from `feat.` to `&` can still yield `NONE`. The builder keeps the full artist credit and requires a matching project-folder artist for a title-only filename.

| Row fields | `must` |
|---|---|
| Neither version field supplied | `None`. For the existing `original/unspecified` case, plain, Original, Main, and Extended filename forms are eligible. |
| `remixer` only | Normalized `<remixer> remix`. |
| `mix_name` only | Normalized `mix_name`. |
| Both | Normalized `mix_name` if it already contains the full remixer name. Otherwise, prefix it with the remixer. |

`exact` stays `None`. It takes a complete filename, including any delivery suffix, and using it suppresses notes. `scan()` returns three lists: ranked `(score, path)` candidates, `(reason, path)` notes, and missed `(filter, value)` pairs. Since `must` can match a folder name alone, the builder checks the filename and selects the first acceptable candidate in resolver order. Each pick gets one `MASTER` or `NONE` line, plus every note returned for that pick.
